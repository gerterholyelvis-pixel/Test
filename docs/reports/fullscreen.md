# Fullscreen report
Causes found: no exitFullscreen calls except the explicit toggle; fullscreen already targets documentElement. Real drops: (1) every screen change (death, win, spectate, queue cancel, reconnect, retry) does location.reload(), which always leaves fullscreen; (2) Esc leaves pointer lock and, in some browsers, fullscreen too (panels/shop/inventory close on Esc).
Fix (menu.js FULLSCREEN block): wish stored in localStorage gk.fsWish (set by F/button/checkbox/Start); retaken on the next trusted pointerdown/keydown (throttled 800 ms, never on Esc); navigator.keyboard.lock(['Escape']) while fullscreen so Esc stays with the game (holding Esc still leaves, and clears the wish). game.js: a non-Esc keypress in play re-takes pointer lock (click already did). index.html: help text.
Not tested in a real browser (fullscreen needs a real gesture; headless cannot confirm). npm test: security tests fail only because the worktree lacks the three/ module (404), unrelated; bots test flaked once and passed on rerun.
